# UTP Portfolio Catalogue

Use for /catalogue, /printspace, /utp, /printer, /build-assist, /circular-feed, or requests to determine what printable/hybrid technology can be made, assembled, qualified, taught, repaired, or expanded within the current CGX/Römer/Eco/Raphael portfolio.

This is a workflow skill, not a new runtime, solver, authority, or technology catalogue. Reuse the Drive-owned catalogue and current Git mirror. Do not create parallel PT/PMX/UTP IDs.

## Canonical basis

Prefer, in order:

1. current owning Drive records, including the Type 1 Römer Cognigrex printable/post-mix/UTP surfaces;
2. current CGX object/source/recovery context and receipts;
3. current Git implementation mirrors for the printable technology catalogue, printable solid-state portfolio and printable extension contracts;
4. external evidence only when the user asks for expansion/verification or when a current safety/material/standards fact is required.

Resolve the live source before relying on a dated filename. Newer owner truth wins.

## Required interpretation

Treat printable technology as a composition of materials, geometry, interfaces, process, environment, energy, seed components, software/control and evidence.

The physical object may be a thin .cgx endpoint. It does not need smartphone-class onboard compute. It may carry stable identity, capability manifest, bounded local state, sensing/actuation interfaces and safe local control while delegating heavier computation through the registered CGX node-exchange/lease/readback model.

Never equate delegated network functionality with semiconductor density, independent compute capacity, certification, or semantic authority.

## Three-plane contract

Every resolved object or build family should map:

- Filespace — stable identity, semantics, configuration, recipes, geometry/BOM/BOP references, material passports, provenance, evidence and authority ceiling.
- Dataspace — live state, telemetry, solver inputs/results, alerts, execution requests, leases and receipts.
- Printspace / solid-state physical space — material layers, voids/cavities, interfaces, structures, conductors, fields, sensors, actuators and service boundaries.

Bind the planes through: Snapshot -> Hash -> Handshake -> Execute/Test -> Readback -> Receipt -> Reviewed Promotion.

A representation bridge does not transfer authority.

## Workflow

1. Run the normal CGX handshake/context resolution.
2. Identify the requested function/technology/system, actor mode, local horizon, scale/environment, target evidence/DIY level, and available materials/tools/seed components/energy when known.
3. Match existing stable catalogue IDs before proposing new child objects.
4. Compose the minimum sufficient function stack: skeleton; material/feed family and concentration basis; functional layers; cavities/channels; interfaces/service islands; process verbs; global/local environment; and seed items not yet printable at that horizon.
5. Recognize process verbs: ADD, MIX, DILUTE, GRADIENT, INFILTRATE, EVAPORATE/DEGAS, CURE, SINTER/ANNEAL, FILM/PLATE, REMOVE/PATTERN, DOPE, STRETCH, POLARISE/MAGNETISE, FILL, EVACUATE, SEAL, TEST and REPAIR.
6. Map the object to the three planes and a thin .cgx identity envelope.
7. Apply selector lens: Cognigrex for lineage/triplet integration; Raphael for physics/falsifiers/solvers; Römer-Grex for manufacturing/Mark/Luke/ISRU/logistics; Eco-Grex/Athene for recovered feed/ecology; LightSpeed/Neo for execution/queues/receipts; Achilles/EMASSC for evidence/custody/governance/release.
8. Separate supported capability from architecture, R&D, source-only, simulation and physical validation.
9. State the next smallest test that can raise the evidence ceiling.
10. When requested, add an outreach/build-assistant view without deleting technical/evidence fields.

## Actor modes

- DIY / education / maker — benign materials, passive/low-energy functions, guided assembly, explicit stop/escalation points.
- Business / workshop — calibrated process cells, material passports, QA, repair/manufacturing recipes and competency gates.
- Government / infrastructure — standards, cyber/physical security, public safety, procurement, geospatial asset state, lifecycle and audit.
- Nonprofit / cleanup / community — distributed collection/observation/benign assembly backed by a small qualified technical core; volunteer status never grants specialist authority.
- Internal Römer/EMASSC R&D — full architecture visibility while physical, mission, legal and release gates remain explicit.

## Local horizons

Recognize TERR, OCEAN, ORBIT, LUNAR, MARS, ASTEROID, INTERPLANETARY and INTERSTELLAR.

A local horizon is the bounded set of materials, energy, processes, tools, evidence, communications and authority currently available. Self-organising means federated planning, handshake, capability discovery and safe fallback. It never means autonomous governance, resource ownership, extraction authority or uncontrolled self-replication.

## Material/ecology rule

Recovered/ocean/land/ISRU feed is only a candidate resource until collection provenance, sorting, decontamination, assay, uncertainty, processability and application-specific safety/quality gates pass.

Prefer local bulk + recycled bulk + scarce specialty concentrate where appropriate. DILUTE/DOPE may localize high-function material, but material compatibility and empirical qualification remain hard constraints.

Graphene/carbon is one candidate conductor/electrode/feed family. Do not default to it without measured comparison.

## Evidence and safety

Never uplift architecture to physical proof; simulation/Raphael output to empirical proof; thin endpoint to smartphone-class onboard compute; void/free space to energy source; cleanup feed to product-qualified feed; local resource class to printer-grade material; recursive manufacturing to unlimited autonomous self-replication; planning/tagging to deorbit/deflection/extraction/mission/governance authority; or geospatial/resonant control architecture to biological/health efficacy.

High voltage, pressure/vacuum, reactive chemistry, energetic processes, electrochemistry, semiconductor processing, orbital actions and ecological release require their own qualified procedures and authorities.

## Output contract

Return a compact structured response containing:

1. Object / stable IDs
2. Requested function and actor/horizon
3. Capability state — supported / architecture / R&D / gated / unknown
4. Function stack — materials, geometry, interfaces, process, environment, seed parts
5. .cgx identity envelope — object ID/revision, capability manifest, local state/I-O, delegated-compute route, safe-state boundary
6. Three-plane mapping — filespace / dataspace / printspace
7. Local-resource map — local, recovered, imported/specialty, reject/unknown
8. Validation/evidence ceiling
9. Next smallest test / falsifier
10. DBR state — snapshot/hash/handshake/readback/receipt/promotion status
11. Escalations / prohibited assumptions

When a public-facing or outreach catalogue is requested, add a plain-language “Can I build this here?” summary, but keep stable IDs and evidence ceiling attached.

## Portfolio expansion rule

A new PT/UTP child record is justified only when the requested object cannot be represented as a configuration/composition of existing primitives and interfaces. Prefer geometry/material/process configurations over multiplying technology categories.
