## Authority and epistemic translation

CGX topology does not change the existing authority hierarchy. Each object needs separate fields for:

- `source_authority`: owner, Achilles gate, project canon, ACR3, Drive/Git/local receipt or historical source;
- `evidence_class`: Known, Derived, Hypothesis, Conceptual Model, Requires Validation or Unknown;
- `lifecycle_state`: observed, verified, accepted, persisted, published or superseded;
- `release_class`: private-local, internal-review, owner-gated, public-ready candidate or prohibited;
- `canonical_destination`: an exact workbook/range, repository/ref, Drive object or local execution store;
- `receipt`: hash, revision, timestamp, tool/version, method, assumptions, units, uncertainty and readback.

`Resolve` may promote an Overlay only when the relevant authority gate, deterministic receipt and destination readback all exist. A successful simulation, render, CI run or local receipt remains derived implementation evidence.

## Assimilation and cleanup pipeline

```text
Discover → hash/inventory → authority classify → type/epistemic classify
→ reference or import to Overlay → adapter/conformance test → contradiction review
→ owner/appropriate gate → Resolve → destination write → exact readback
→ supersession link → archive candidate → separately authorised removal
```

Rules:

1. Preserve native bytes and original location/ID before creating any CGX projection.
2. Use references for large, controlled, licensed, online-canonical or frequently changing sources.
3. Treat duplicates as candidates until hashes, semantic coverage, authority and provenance are reconciled.
4. A `.txt` build note may be superseded only after its unique facts and lineage are linked into the accepted successor.
5. Do not flatten workbooks, CAD assemblies, simulations or agent ledgers into generic documents.
6. Never delete a unique or unresolved item; archive-before-delete remains mandatory.
7. Keep old Type 1 `CGX` naming as historical precursor terminology. The new `.cgx` carrier receives a distinct schema/profile ID.
8. Corpus cleanup begins with a read-only inventory manifest, not file movement.
